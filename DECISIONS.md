# Decisions

One line per decision taken while building, newest last. Format: `YYYY-MM-DD — decision — why`.

- 2026-10-22 — Go module path is `pgbackup` — plan.md Phase 1 default; no answer to the ASK yet, rename later with `go mod edit -module` plus `gofmt -r` if a hosted path is wanted.
- 2026-10-22 — Pinned Go 1.27 and Alpine 3.24 in the Dockerfile — current stable at the time; `golang:1.27-alpine` is itself based on Alpine 3.24, and Alpine ships `postgresql16/17/18-client`.
- 2026-10-22 — `S3_ENDPOINT` is a URL with scheme (`http://` or `https://`) and the scheme selects TLS — one variable instead of endpoint + `S3_USE_SSL`; `S3_TLS_INSECURE` only disables certificate verification.
- 2026-10-22 — The developer host (Windows) has neither Go nor `make`; all checks run through Docker (`golang:1.27-alpine` for unit tests, `test/compose.yml` for integration) — the Makefile stays the canonical interface for hosts that have both.
- 2026-10-22 — Integration stand uses Garage (`dxflrs/garage:v2.1.0`) instead of MinIO — `minio/minio` was archived upstream on 2026-04-25 and its images are no longer publicly pullable; Garage is a 39 MB single-binary S3 server with multipart, `ListMultipartUploads` and the `AbortIncompleteMultipartUpload` lifecycle rule. It lacks Object Lock and tagging, so those tests are skipped on the stand. (Supersedes the earlier Chainguard-MinIO choice made the same day.)
- 2026-10-22 — `config.Load` validates only what every subcommand needs; key-material requirements live in `ValidateForBackup`, `ValidateForServe` and `ValidateForRestore` — `list`, `prune` and `health` must run without any age key, so "exactly one of AGE_RECIPIENTS / AGE_PASSPHRASE" is enforced by the backup commands, while setting both is rejected by `Load` for everyone.
- 2026-10-22 — `AGE_RECIPIENTS` accepts `_FILE` but is not redacted (`Spec.File` vs `Spec.Secret`) — recipients are public keys and seeing them in logs is useful when rotating keys.
- 2026-10-22 — Child processes get an allow-listed environment (`PATH`, `HOME`, `TMPDIR`, `TZ`, `LANG`, `LC_*`) plus the libpq variables we set, never the full process environment — the S3 and age secrets have no business inside `pg_dump`; `internal/pg.inheritedEnv` is the list.
- 2026-10-22 — Cancellation of a client tool uses `exec.Cmd.Cancel` (SIGTERM) with `WaitDelay` = 10 s before SIGKILL — the plan's "SIGTERM, wait 10 s, SIGKILL" is exactly what the standard library offers; no custom process-group handling.
- 2026-10-22 — `S3Store.Put` aborts a failed multipart upload itself with a context detached from the caller's (`context.WithoutCancel`, 30 s) — the SDK's own abort runs on the caller's context, so a cancelled backup left incomplete uploads behind on Garage; a second abort after the SDK's is harmless (`NoSuchUpload` ignored). Found by `TestIntegrationCancelledMultipartLeavesNothing`.
- 2026-10-22 — `S3Store.Delete` ignores per-key `NoSuchKey`/`NotFound` entries in the `DeleteObjects` response — AWS is silent about missing keys, Garage reports them; the interface promises idempotent deletes.
- 2026-10-22 — Garage returns user metadata (`x-amz-meta-*`) on HEAD and GET, so the metadata round-trip test runs for real on the stand; it still skips rather than fails on a server that drops metadata, because manifests remain the source of truth.
- 2026-10-22 — Manifest key = object key with `.age` → `.manifest.json` (`app_<ts>.dump.manifest.json`, `globals_<ts>.sql.zst.manifest.json`), not `<name>_<ts>.manifest.json` — a database literally named `globals` would otherwise share a manifest key with the globals file. `/` and `%` in database names are percent-encoded in keys.
- 2026-10-22 — The age stream is finalised only after `pg_dump` exited 0 — the producer goroutine calls `Wait` before `Close` on the encryptor, so a dump that fails mid-way closes the pipe with its error, the uploader sees a reader error and aborts; a partial dump can never complete into a visible object. When `Put` fails first, the context is cancelled (SIGTERM to `pg_dump`) and the `Put` error is reported as the cause, not the resulting cancellation.
- 2026-10-22 — Object metadata carries only `pgbackup-created-at` and `pgbackup-tool-version`, not the SHA-256 — the hash is known only after the upload completes and S3 metadata cannot be set afterwards without a copy; the manifest is the source of truth for the hash (plan.md §9 item 6 adjusted).
- 2026-10-22 — `BACKUP_RETRIES` is the total number of attempts (minimum 1), not the number of retries after the first — matches the variable's documentation; transient = anything that is not a tool exit error, an integrity failure, missing key material, a missing object/bucket, or a dead context.
- 2026-10-22 — `pg_restore --list` reads only the table of contents and exits without consuming the archive — `verify` (Phase 8) must keep reading the decrypted stream to EOF after `pg_restore` exits, otherwise neither the SHA-256 nor age's per-chunk authentication covers the whole object. Found in the Phase 6 integration test.
- 2026-10-22 — Retention periods count the N most recent days/weeks/months *that have a backup*, not calendar periods back from now — a paused schedule then never silently shrinks what is kept (same semantics as borg/restic); ISO weeks, UTC. The newest dump of every database is always kept, whatever the policy.
- 2026-10-22 — Prune removes orphans, dangling manifests and unreferenced globals only when the timestamp in their key is older than 24 h (`DefaultOrphanAge`) — the key time is the run start, so anything younger may belong to a run still in progress; the object's `LastModified` is not consulted because it is always "now" for a fresh upload. Manifests are deleted before objects so an interrupted prune leaves orphans (self-healing), never manifests pointing at nothing.
- 2026-10-22 — Catalog (`manifest.Load`) treats manifests as the source of truth: objects without a manifest are reported as orphans, manifests without an object as dangling, unparsable manifests as broken (never deleted automatically), and keys outside the layout as foreign (never touched).
- 2026-10-22 — Restore decrypts through an `errRecorder` so an age authentication failure is reported as exit 4 even though `pg_restore` only sees "unexpected end of file" — the SDK/pipe otherwise hides the root cause. In stream mode the hash is compared after `pg_restore`; in spool mode before it. A manifest whose hash does not match an intact object still exits 4 after the restore completed: the data is authentic, but the object is not the one described.
- 2026-10-22 — `verify --full` requires relations in the scratch database only when the archive's table of contents lists TABLE/SEQUENCE/VIEW entries — a backup of an empty database is valid and must verify clean. Found by the CLI test against the stand's empty `test` database.
- 2026-10-22 — Globals are replayed with `ON_ERROR_STOP=0` and the ERROR lines are counted, not fatal — on any cluster that already has the roles, every `CREATE ROLE` fails with "already exists"; the count is reported so an operator notices a real problem.
- 2026-10-22 — The database for `restore` is created by us (`CREATE DATABASE ... TEMPLATE template0`), never by `pg_restore --create`, so `--target-db` renames work and `--owner` applies uniformly; `DROP DATABASE ... WITH (FORCE)` is used on servers ≥ 13 after terminating sessions.
- 2026-10-22 — pg_dump ≥ 17.6 wraps plain-text dumps in `\restrict <random token>` … `\unrestrict`; schema comparisons in tests strip those lines. Irrelevant to custom-format archives, which is what backups use.
- 2026-10-22 — Health treats the process start (`<state-dir>/started_at`, written by `serve`) like a success until the first run — otherwise a fresh deployment without `RUN_ON_START` would be "unhealthy" until its first scheduled backup, possibly a day later. After that, only `last_success` counts; the window is `HEALTH_MAX_AGE` or twice the schedule interval capped at 26 h.
- 2026-10-22 — SIGTERM cancels a running job immediately (SIGTERM to `pg_dump`, multipart aborted) and `serve` exits 1 if a job was interrupted, 0 if idle — waiting for a multi-hour dump to finish would defeat container orchestration; the aborted run leaves nothing behind by design. Jobs that ignore cancellation are abandoned after `SHUTDOWN_TIMEOUT`.
- 2026-10-22 — Overlapping firings are skipped by the scheduler's own per-job lock rather than `cron.SkipIfStillRunning` — the lock also covers the `RUN_ON_START` run and is unit-testable; `cron.Recover` is kept so a panic in a job cannot kill the scheduler.
- 2026-10-22 — Metrics are written by hand in the Prometheus text format (8 gauges, 1 counter family) — a client library for nine series is not worth a dependency.
- 2026-10-22 — The build stage runs on `$BUILDPLATFORM` and cross-compiles with `GOOS`/`GOARCH`; only the Alpine runtime stage runs under emulation for arm64 — building Go under QEMU would be several times slower for nothing. Local arm64 builds need `docker run --privileged --rm tonistiigi/binfmt --install arm64` once per Docker VM (Docker Desktop advertised arm64 but had no binfmt handler registered); CI uses the equivalent QEMU setup action.
- 2026-10-22 — The runtime image smoke test (`make test-image`, `test/image_smoke.sh`) runs the real image with `--read-only --tmpfs /tmp` through backup, list, verify --full, restore, a refused restore, health and serve + SIGTERM — this is the end-to-end check of the artifact that ships, separate from the Go test suite. `HOME=/tmp` in the image so libpq's optional `~/.pgpass` lookup never hits the read-only root.
- 2026-10-22 — Keep `feature/s3/manager` although staticcheck reports it deprecated in favour of `feature/s3/transfermanager` — transfermanager is v0.4.x (published the day before this decision), not stable, with an API that is still changing; the uploader is the one piece of the backup path that must not move under us. SA1019 is file-ignored in `internal/store/s3.go`. Revisit when transfermanager reaches v1: the Garage integration tests (abort on failure, abort on cancel, 100 MiB round trip) are the acceptance test for the migration.
- 2026-10-22 — CI is GitHub Actions: `lint` (gofmt, vet, staticcheck via `go run`), `unit` (-race, coverage artifact), `vuln` (govulncheck), `integration` matrix over PostgreSQL 16/17/18 using the compose stand, `build` (bake, amd64+arm64, no push), `image` (size gate, Trivy HIGH/CRITICAL with `ignore-unfixed`, read-only smoke test). Release on `v*` tags: bake push to ghcr.io, cosign keyless signatures by digest, SPDX SBOM per major attached to the GitHub release. Every CI job calls a Makefile target so the same command runs locally.
- 2026-10-22 — A fresh-context agent reviewed README/RUNBOOK/compose.example.yml as an operator and ran the documented commands against the stand; every command, flag and exit code matched, and the review produced four code changes: `health` reads only its own variables (`config.LoadHealth`) so a probe needs no S3 credentials; `-h` no longer prints the `flag.ErrHelp` sentinel; restore pre-flight proves the spool directory is writable (a read-only mount used to pass `--dry-run` and fail the real run); `PGDATABASE` names the maintenance database instead of a hard-coded `postgres`; `list` flags a size mismatch between bucket and manifest. The remaining findings were documentation gaps and are fixed in the docs.
- 2026-10-22 — The S3 HTTP transport has a 2-minute `ResponseHeaderTimeout` — a server that accepts a part upload and never answers would otherwise stall the run until `BACKUP_TIMEOUT` (6 h by default); the timeout starts after the request body is sent, so large parts are not cut off, and the SDK retries the part. A short S3 outage (the fault-injection scenario pauses Garage for 15 s mid-upload) is therefore survived, a dead server fails the run within minutes.
- 2026-10-22 — Secrets review for v0.1.0: every occurrence of `PGPASSWORD`, `SecretKey`, `Passphrase`, `Identity` in non-test code is a field, a configuration read, a redaction site (`Config.Redacted`) or a message naming the *variable*; no error path formats a secret value, `Config.String` is the only stringer and redacts, child-process arguments (the only thing `pg.Runner` logs) never carry secrets because the password travels in the child's environment, and `crypt.ParseIdentities` errors by index rather than echoing the key. Public age recipients are deliberately visible.
- 2026-10-22 — Fault injection (`make test-faults`, `test/fault_injection.sh`) runs the runtime image against the stand with PostgreSQL and Garage throttled to 0.1 CPU (`docker update --cpus`), because at full speed a 290 MB run finishes in a second and timing-based injection lands after the fact. Results on 2026-10-22: (A) Garage paused for 15 s in the middle of a 42 s upload → the stalled part resumed, run exit 0, 4 objects, 0 incomplete uploads; (B) PostgreSQL restarted mid-dump → `pg_dump exited with code 1`, 1 attempt (not retried), no dump object, 0 incomplete uploads, next run ok; (C) `docker stop` during an upload under `serve` → "shutdown aborted a running job", exit 1, no dump object, 0 incomplete uploads. Scenario B also showed that the stand's PostgreSQL loses its tmpfs on restart (a stand artifact, not a product behaviour).
- 2026-10-22 — RUNBOOK §2 restore drill performed on 2026-10-22 without pgbackup (`make drill`, `test/manual_drill.sh`): objects downloaded with a plain S3 GET, `sha256sum` matched the manifest, the `age` CLI (v1.3.2) decrypted the archive, `pg_restore --exit-on-error -j 4` restored 20 000 rows and a sequence value into a fresh database, globals replayed through `age -d | zstd -d | psql` with the expected "already exists" error. The drill is scripted so it can be repeated monthly; record each run here.
- 2026-10-22 — `v0.1.0` is ready to tag: CHANGELOG has the entry, the version is injected at build time from the tag by the release workflow. Tagging (and the first commit) is the owner's step; this repository was built without commits by request.
- 2026-10-22 — License changed from the Phase 1 placeholder (MIT) to **Apache-2.0**, copyright Rapalon Labs, Inc., with a NOTICE file — a company-backed open-source backup tool lives on adoption and trust, which a permissive license serves best; Apache-2.0 adds the explicit patent grant and contribution terms (§5) that MIT lacks. Copyleft (AGPL) was considered and rejected: it would reduce adoption in companies that forbid it in infrastructure while not protecting against the realistic competitor scenario (the network clause does not apply to a backup daemon). All dependencies are permissive (BSD-3, Apache-2.0, MIT), so any outbound license was possible.
- 2026-10-22 — Repository is `https://github.com/rapalon/pg-backup-s3`: the Go module is `github.com/rapalon/pg-backup-s3` (renamed from the Phase 1 placeholder `pgbackup`, imports and ldflags updated), published images are `ghcr.io/rapalon/pg-backup-s3:<PG_MAJOR>` (the release workflow derives the name from the repository), while the binary and the local image tag stay `pgbackup`.
- 2026-10-22 — First CI runs on GitHub: two lessons. (1) A `run: make … | tee log` step without `shell: bash` has no `pipefail`, so the job reported success while `go test` had failed; every piped step now sets `shell: bash` explicitly. (2) `go build` inside the test container failed on the runner because the checkout is mounted with a foreign owner and git refuses VCS status ("dubious ownership"); test builds pass `-buildvcs=false`, and `.dockerignore` keeps `.git` out of the image build context. Diagnosed without log access by emitting the `go test` summary as check-run annotations, which the public API serves.
- 2026-10-22 — S3 client is `aws-sdk-go-v2` (`service/s3` + `feature/s3/manager`), not `minio-go` — `minio-go` is still released (v7.4.1, October 2026) but its owner archived the server and moved to a commercial product; the AWS SDK is the reference client every provider tests against. Third-party servers need `RequestChecksumCalculation`/`ResponseChecksumValidation = WhenRequired`; `config.LoadDefaultConfig` is never used so no implicit credentials are read.
- 2026-10-22 — Image size gate set to 36 MiB — first build of `pgbackup:18` (Alpine 3.24 + postgresql18-client + 1.8 MB binary) measured 33 MiB uncompressed, 10.5 MB compressed; plan.md Phase 10 says measured + 10 %.
- 2026-10-22 — Image size gate raised to 51 MB — with the complete binary (AWS SDK, age, zstd) `pgbackup:18` measures 46 MB uncompressed / 13.6 MiB compressed; the client package is ~25 MB of that, the binary ~14 MB. Measured by `docker images`, which reports the uncompressed layer sum regardless of the storage driver (`docker image inspect .Size` is the compressed content size under containerd).
